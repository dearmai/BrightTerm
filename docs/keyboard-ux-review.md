# 키보드 UX 탐색 — 2026-11-12

## 반영한 개선

- 서버 목록의 실제 표시 순서(즐겨찾기·최근 접속·펼친 폴더·서버)에 따라 ↑↓, Home/End로 탐색한다. 접힌 폴더 안의 항목은 건너뛴다.
- 폴더는 ←→, Enter/Space로 조작하며 ←로 상위 폴더에 돌아간다. 검색 시에는 결과를 보여주기 위해 폴더가 펼쳐진다.
- Tab으로 목록 진입, 검색창 ↑↓로 목록 이동, 목록 Esc로 검색 복귀를 지원한다. 현재 위치를 테두리로 표시하고 스크롤한다. 이동만으로 연결하거나 터미널에 포커스를 넘기지 않는다.
- Enter 연결과 분할 연결, F2 편집, Delete 삭제 확인은 목록 자체에 포커스가 있을 때만 처리한다. 행 안의 버튼에는 기본 키보드 동작을 유지한다.
- 검색 Enter는 저장 배열 순서 대신 표시 순서의 첫 서버에 한 번 연결한다. 기존에는 검색 Enter가 상위 핸들러로 전파되어 선택된 다른 서버도 열 수 있었다. 검색 중 F2/Delete가 서버에 적용되는 경로도 제거했다.
- 한글 조합 중 Enter와 키를 길게 누를 때 반복 연결·편집·삭제를 방지한다. 활성 항목은 `aria-activedescendant`로 노출한다.

## 후속 개선 후보

1. **우클릭 메뉴 키보드 조작** — `components/ui.tsx`의 ContextMenu는 Escape 닫기만 직접 처리한다. 메뉴를 열 때 첫 항목에 포커스를 두고 ↑↓, Home/End, 하위 메뉴 ←→, Shift+F10/메뉴 키 호출 및 닫은 뒤 원래 위치 복원을 함께 설계하면 서버 관리 전체를 키보드로 처리할 수 있다.
2. **대화상자 포커스 수명 관리** — 공통 Modal에는 Tab/Shift+Tab 순환 제한과 호출 위치로의 복원이 없다. 닫을 때 터미널에 포커스를 주는 개별 동작도 있어 목록 편집 뒤 복귀를 공통으로 정리할 필요가 있다. 중첩 확인창·입력창도 함께 검증해야 한다.
3. **빠른 접속의 경계 처리** — QuickConnect의 ↓는 결과가 0개일 때 인덱스를 -1로 만든다. 결과 수 변화 시 인덱스를 보정하고 Home/End, 한글 조합 중 Enter 방지, 활성 결과 접근성 표시를 함께 개선할 수 있다.
4. **검색으로 바로 이동하는 단축키** — 전역 단축키는 터미널·편집기와 충돌할 수 있다. 기존 Ctrl+K 빠른 접속과의 역할을 정하고 설정의 단축키 안내와 함께 제공하는 편이 좋다.

후속 후보는 코드 탐색 결과이며 이번 변경에는 포함하지 않았다. 스크린리더, Linux/macOS 실행과 배포 패키지 검증은 수행하지 않았다.
