# 회고록

## 2026-11-12 — 같은 기능을 다른 런타임으로 옮길 때

### 잘된 점

- 데스크톱 중계를 Java 로 옮기면서 단위 테스트를 데스크톱 테스트와 같은 바이트 입력으로 만들어 두 구현이 같은 결과를 내는지 맞췄다. 오류 코드(103·105)가 짐작과 다르다는 것도 데스크톱 코드를 대조해 바로 잡았다.
- IronRDP 가 마우스 좌표를 getBoundingClientRect 로 계산한다는 것을 소스에서 확인하고, 확대·이동을 CSS 변환으로 처리해 좌표 변환 코드를 따로 두지 않았다.
- 소프트 키보드 문제(IronRDP 는 자기 요소에 포커스가 있을 때만 키를 보냄)와 클립보드 문제(WebView 는 읽기 권한 없음, Android 12+ 알림)를 실제 소스·플랫폼 동작으로 확인한 뒤 해결했다.
- 사용자의 실제 환경(점프 호스트 경유)을 e2e 로 재현해 확인했고, 개인 기기에서는 자동 테스트를 돌리지 않았다.

### 아쉬운 점과 다음 적용

- WebView 의 cleartext 차단(network_security_config)을 처음 설계에서 놓쳐 첫 e2e 에서야 알았다. Android 에서 로컬 서버를 쓸 때는 네트워크 보안 설정부터 확인한다.
- CSS 의 display 규칙이 hidden 속성을 덮어쓰는 실수를 데스크톱(.tab 클래스 충돌)에 이어 또 했다. 새 화면은 스크린숏을 먼저 보고, display 를 주는 요소에는 [hidden] 규칙을 같이 둔다.
- 컨테이너의 X 세션은 그 사용자로만 열린다는 것을 데스크톱 테스트에 이미 적어 두고도 다시 헤맸다. 같은 기반 시설은 기존 테스트의 보조 함수를 먼저 가져다 쓴다.

## 2026-11-12 — 라이브러리가 못 하는 것은 길목에서 한다

### 잘된 점

- IronRDP 웹에 화질·소리 설정이 없다는 것을 d.ts·JS·WASM 문자열까지 확인한 뒤, 중계가 TLS 를 직접 풀고 있다는 구조를 이용해 접속 PDU 의 고정 길이 필드만 고치는 방법을 택했다. 실제 IronRDP 접속에서 고친 기록을 확인하고, 형식을 모르면 손대지 않게 했다.
- "연결 중에서 멈춤"을 짐작으로 고치지 않고 단계 기록을 화면에 먼저 보였다. 사용자가 보낸 한 장의 화면으로 NLA·TLS 는 통과하고 15비트 직후 멈춘다는 것을 바로 좁혔다.
- 재현할 수 없는 Windows 동작(15비트 멈춤)은 테스트용 지연 스위치로 흉내 내 자동 재연결 경로를 끝까지 확인했다.
- ⌘Tab 은 전역 단축키로 막을 수 없다는 점을 먼저 짚고, 원격 데스크톱 앱들이 쓰는 시스템 단축키 끄기를 임시 폴더에서 실제로 부른 뒤에 넣었다. x64·arm64 바이너리 포함과 패키지 로드까지 확인했다.

### 아쉬운 점과 다음 적용

- 탭 안 RDP 화면에 class "tab" 을 붙여 탭 표시줄 스타일과 겹쳤다. 테스트는 통과했고 스크린숏을 보고서야 알았다. 새 화면은 스크린숏을 꼭 보고, 공용 이름(tab, pane 등)은 접두어를 붙인다.
- 화질 패처를 처음에 모든 단위를 붙잡아 모으게 만들어, 계산이 틀리면 접속이 멈출 수 있는 구조였다. 고칠 대상만 모으고 나머지는 흘리는 방식이 처음부터 맞았다.
- connect() 가 경고를 지우는 것을 놓쳐 재연결 안내가 사라졌다. 상태를 지우는 함수 안에서 남겨야 할 값은 따로 둔다.
- e2e 가 연결을 남긴 채 끝나면 종료 확인 창에 막힌다는 것을 사용자가 먼저 알려 줬다. 확인 창이 있는 앱의 e2e 는 처음부터 강제 종료 도우미로 닫는다.

## 2026-11-12 — 남의 설정 파일에 쓰는 기능과 비밀값 보기

### 잘된 점

- ~/.ssh/config 본문에 블록을 끼우면 사용자 전역 옵션의 소속이 바뀌고 앞의 Host * 에 값이 가려진다는 OpenSSH 해석 규칙을 먼저 따져, 별도 파일 + 맨 앞 Include 로 설계했다. 실제 ssh -G 와 ProxyJump 실제 로그인으로 확인했다.
- 사용자 파일을 바꾸는 기능이라 되돌림(모두 끄면 원래 내용 그대로), 줄바꿈·심볼릭 링크 보존, 자동 동기화를 끈 PC에서는 아무것도 건드리지 않음을 E2E로 바이트 단위까지 확인했다.
- Windows 기본 OpenSSH가 다른 사용자 권한이 있는 설정 파일을 거부한다는 점을 실제 실행으로 발견하고, 실제 ~/.ssh ACL 조건을 확인해 기록했다.
- 비밀번호 보기에서 "본 값을 그대로 저장"이 공유 계정을 새 계정으로 가르는 부작용을 저장 로직을 읽고 미리 막았고, E2E로 볼트 항목 변화가 없음을 확인했다.

### 아쉬운 점과 다음 적용

- 테스트 기대값을 실제 출력 확인 전에 적어 여러 번 고쳤다(ssh -G의 [주소] 표기, 공유 계정이 공유 모드로 열리는 동작, 비동기 채움 대기). 기대값은 실제 출력이나 코드 경로를 먼저 보고 정한다.
- Git Bash의 sed·node -e 인라인 치환에서 이스케이프가 깨져 \b가 백스페이스 문자로 들어간 일이 있었다. 정규식이 들어가는 치환은 스크립트 파일(String.raw)이나 Edit 도구로 한다.
- 상대 경로 Include 의 Windows 기본 OpenSSH 동작은 실제 ~/.ssh 를 쓰지 않고는 확인할 수 없었다. 사용자가 원하면 실제 환경에서 한 번 확인한다.

## 2026-11-12 — 생성 파일의 환경 차이는 생성기에서 없앤다

### 잘된 점

- "그것도 커밋해"라는 요청에 바로 커밋하지 않고 diff를 먼저 봤다. 이전 커밋이 의도적으로 넣은 고지를 지우는 변경임을 확인하고 근거와 함께 되물었다.
- gitignore 제안에는 파일이 README 링크·패키지 동봉·법적 고지로 쓰인다는 점을 확인해 추적 유지와 결정적 생성으로 답했다. 결과가 HEAD와 바이트 단위로 같은지, 반복 실행에도 같은지, 근거가 없을 때 조용히 빠지지 않고 실패하는지까지 확인했다.

### 아쉬운 점과 다음 적용

- 같은 OS 차이가 작업내역서에 세 번이나 "커밋에서 제외"로만 기록되고 방치됐다. 반복되는 환경 차이는 피하는 대신 원인(생성 입력이 OS별 설치 상태에 의존)을 고친다.
- 처음 구현에서 줄바꿈을 정규화해 차이가 났다. 원문을 보존해야 하는 파일은 정규화하지 않는다.

## 2026-11-12 — 접속 진단은 실제 출력에서 고른다

### 잘된 점

- 줄을 고르는 규칙을 짐작으로 만들지 않고, podman sshd에서 비밀번호 틀림·사용자 없음·닫힌 포트의 ssh2 debug 원문을 먼저 수집해 그대로 단위 테스트 입력으로 썼다.
- E2E에서 화면 안내 '접속 실패' 문구가 진단에 한 번 더 섞이는 것을 발견했다. 문자열 패턴으로 거르지 않고 기록 경로(debug와 add)로 구분해 근본적으로 막았다.
- 자동 재접속 반복 시 진단이 계속 쌓이지 않도록 같은 원인은 생략하고, 비밀번호가 화면에 나오지 않는 것을 E2E에서 확인했다.

### 아쉬운 점과 다음 적용

- 공개키·점프 서버·프록시 실패는 실제 서버로 확인하지 않았다. 해당 사례가 들어오면 같은 podman 이미지에 키·점프 구성을 추가해 E2E로 넓힌다.
- 접속 후 끊김(keepalive 시간 초과, 서버 종료)도 원인 파악 요구가 생길 수 있다. 그때는 마지막 수신·DISCONNECT 줄을 같은 방식으로 요약한다.

## 2026-11-12 — 실제 셸로 확인해야 보이는 호환성 문제

### 잘된 점

- 셸 의존 코드(유휴 방지, TMOUT 조회, 셸 명령 파일 관리, tmux 입력 줄, 자동 실행)를 먼저 추린 뒤 컨테이너에서 각 셸의 TMOUT 출력을 직접 찍어 봤다. ksh93이 "timeout"으로 붙여 쓰고 문장이 이어진다는 차이를 E2E 실패로 재현한 뒤 고쳤다.
- AIX 7.2 셸 버전을 자료로 확인하고, 같은 릴리스(93t+ 2009-05-01)의 공개 바이너리를 해시로 고정해 썼다. 재현할 수 없는 ksh88은 pdksh로 대신하되 다른 점(TMOUT 경고 없음)을 테스트와 문서에 그대로 남겼다.
- 범위가 섞인 작업 트리를 커밋 단위로 나누고, 일부만 스테이징한 커밋은 그 트리만 꺼내 타입 검사로 확인했다.

### 아쉬운 점과 다음 적용

- 처음 전체 단위 테스트 실패 4건을 "무관"으로만 보고하고 넘어갔다. 실행 환경 문제라도 원인이 명확하면 그 자리에서 고치거나 건너뜀 사유를 남긴다.
- Windows Git Bash에서 heredoc·따옴표가 섞인 인라인 스크립트가 여러 번 잘렸다. 긴 편집은 Edit/Write나 스크래치 파일 스크립트로 한다.
- 근사 환경의 통과를 실제 AIX 통과로 말하지 않는다. AIX 서버에 접근할 수 있으면 ksh88 TMOUT 경고와 PS1을 실제 출력으로 확인해 단위 테스트에 추가한다.

## 2026-11-12 — 충돌 비교를 데이터 선택에 연결

### 잘된 점

- 실제 계정 비밀값 비교를 메인 프로세스 안에서 수행하고 화면에는 판정만 전달했다. 암호문의 차이와 비밀번호의 차이를 분리해 불필요한 오해를 줄였다.
- 미리보기 자체의 읽기 전용 성질을 설정·볼트·동기화 기록·원격 파일의 전후 비교로 확인했다. 화면에서 비교한 뒤 가져오는 흐름도 기존 E2E에 포함했다.
- 미리보기와 적용을 동일 지문 토큰에 연결하고 로컬·원격 변경 및 잠금 후의 이전 선택 거부를 검증했다. 기존 백업·동기화 회귀 테스트를 유지했다.

### 한계와 다음 적용

- 공통 기준 스냅샷 없이 어느 기기가 최신인지나 추가/삭제의 방향을 알아낼 수는 없다. 현재는 ID별 한쪽 존재·값 차이만 보여준다.
- 미설정과 명시된 기본값은 저장상 차이가 있어 표시하지만 실제 동작은 같을 수 있다. 이를 설명하고 임의 정규화로 저장 의미를 바꾸지 않았다.
- 계정 외에도 명령·메모·스니펫에는 비밀값이 포함될 수 있다. 본문은 명시적인 펼치기로 보고 알려진 자격 증명은 가리며, 자동 병합은 참조 무결성을 설계한 뒤 별도로 다뤄야 한다.

## 2026-11-12 — 동기화 실패 알림과 비교 정보의 구분

### 판단 및 검증

- 실패 알림 구현과 충돌 비교 대책 제안을 구분했다. 어떤 값이 다른지 알 수 없는 기존 화면에서 사용자의 데이터 선택을 대신하지 않았다.
- 현재 동기화가 전체 지문만 저장한다는 점을 확인했다. 항목별 기준 스냅샷 없이 추가·삭제의 방향이나 최신 기기를 단정하는 비교 화면을 제안하지 않았다.
- 반복되는 재시도로 알림이 계속 열리지 않게 하고, 터미널 입력 포커스 유지도 테스트했다. 모의 상태 테스트 결과와 실제 사용자 저장소의 충돌 해결 여부를 구분했다.

### 다음 작업에 적용할 점

- 비교 화면을 구현할 때는 암호문의 차이와 복호화한 실제 값의 차이를 분리하고, 비밀값은 메인 프로세스에서만 비교한다.
- 미리보기 조회가 데이터를 바꾸지 않는지, 비교 뒤 로컬·원격이 바뀌면 선택을 다시 확인하는지 함께 검증한다.

## 2026-11-12 — 마우스 보고 상태와 재접속 경계

### 잘된 점

- 마우스 모드를 끄는 것과 서버로 보고를 보내지 않는 것을 함께 처리했다. 재접속 시 화면을 전부 초기화하지 않고 마우스 상태만 정리해 기록을 보존했다.
- 로컬 TCP 서버를 사용해 사용자 서버를 건드리지 않고 실제 연결 중단·자동 재접속 및 서버 편집 UI의 즉시 반영을 검증했다.
- 마우스 보고를 사용자 입력과 분리해 다른 패널로 브로드캐스트하지 않도록 했다. 혼합 제어문과 패킷 경계도 테스트했다.
- pull 전에 원격 차이와 로컬 수정을 확인하고, 충돌 가능성이 있는 생성 파일만 stash에 보관해 진행 중인 UI 수정을 유지했다.

### 아쉬운 점과 다음 적용

- 앞선 설명에서 숫자열만 보고 urxvt 가능성을 고려했지만, 실제 xterm.js 테스트에서는 해당 모드가 무시되어 X10 응답이 왔다. 화면에 보이는 문자열과 실제 전송 바이트를 구분하고, 지원 여부는 실행 테스트로 확인한다.
- 로컬 Telnet 경로의 성공을 사용자 SSH·tmux 환경 검증으로 확대해 표현하지 않는다. 실제 서버의 프로그램이 마우스 모드를 다시 요청할 때 허용 설정이 정상 동작하는지도 배포 후 확인할 범위다.

## 2026-11-11 — 독립 포크 제품명·버전 정리

### 잘된 점

- `script`가 없는 환경을 고려하지 않아 첫 `TMOUT` 시험이 무효였다. 시험이 실패했을 때 문서 문제인지 시험 문제인지 구분하는 데 한 번 더 돌려야 했다.
- 시스템을 바꾸는 RHEL 명령은 끝내 실행하지 못했다. 다음에는 일회용 VM 같은 환경이 필요하다.

## 2026-11-11 — 포워딩과 재접속 상태를 실제 동작과 연결하기

- 포워딩 설정이 존재하는 것과 리스너 할당, 목적지 TCP 접속, 서비스 인증 성공은 서로 다른 상태다. 표시와 도움말에서 확인 범위를 구분하고, 점검용 연결을 사용자 통계에서 제외했다.
- 여러 터미널이 같은 포워딩을 공유하므로 최초 생성 터미널보다 포워딩의 수명이 길어질 수 있다. 공유 풀과 마지막 사용자 해제 기준을 두고, 최초 터미널 종료 후에도 연결이 유지되는 것을 테스트했다.

- TMOUT은 별도 명령 채널의 환경값과 현재 터미널 셸의 값이 다를 수 있어 실제 셸에서 조회했다. 값을 읽지 못한 경우를 0이나 미설정으로 단정하지 않고 안내한다.

- 로컬 TCP와 모의 SSH 클라이언트 테스트는 상태 전이와 수명·통계를 검증하지만 실제 SSH 정책이나 서버 셸 차이까지 보장하지 않는다. 실제 서버와 다른 OS·패키지 검증은 별도로 남겼다.

## 2026-11-12 — 서버 목록의 키보드 포커스와 이벤트 경계

- 정적 검사·빌드 성공과 앱 실행 성공은 구분했다. Windows 제한 샌드박스의 설치 경로 접근 오류는 승인된 실행 환경에서 재검증했고 제품의 샌드박스 기본값은 변경하지 않았다.
