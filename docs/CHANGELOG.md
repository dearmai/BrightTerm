## 다음 버전 (미배포)

### Android 원격 데스크톱(RDP)

- Android 앱에도 서버 OS 와 원격 데스크톱을 넣었습니다. 서버 편집 → 서버 OS·RDP 설정·허용 상태 확인, 서버 목록 🖥 버튼, 앱 안의 원격 데스크톱 탭(IronRDP, 데스크톱과 같은 고정 버전). 설정은 데스크톱과 같은 형식으로 Git 동기화됩니다.
- 중계는 Java 로 새로 만들었습니다(RdpGateway: 127.0.0.1 WebSocket·RDCleanPath·X.224·TLS 지문 고정·KEY_USAGE 시 TLS 1.2 RSA 재시도·색 깊이/화면 효과/소리 고치기·접속 단계 표시). 경로는 직접·점프 호스트(JSch 로컬 포워딩)·이 서버의 SSH 터널입니다.
- 터치패드 방식 마우스(한 손가락 이동·탭 클릭·두 번 탭 후 끌기·두 손가락 탭 오른쪽 클릭·두 손가락 끌기 화면 이동/스크롤·핀치 확대), 소프트 키보드·특수 키·Ctrl+Alt+Del, 텍스트 클립보드 양방향(Android 12+ 붙여넣기 알림이 반복되지 않게 바뀐 뒤에만 읽음), 화면 위 설정 패널, 15비트 → 16비트 자동 다시 연결.
- 검증: 에뮬레이터(Android 16)에서 `test/e2e-android-rdp.mjs`(설정·허용 상태 확인·인증서 신뢰·연결·터치 동작·소프트 키보드 로그인·클립보드 양방향·설정 저장·15→16비트·탭 닫기), `test/e2e-android-rdp-route.mjs`(점프 호스트·SSH 터널, 경로 SSH 정리), Git 동기화 e2e(Windows 서버 가져오기·RDP 전용 비밀번호 복호화·Android 변경 올리기), 기존 Android e2e, Java 단위 테스트(RdpTest)를 통과했습니다. 실제 Windows(NLA)·실제 휴대폰의 손가락 입력·IME(한글 조합)는 사용자 확인이 필요합니다.

### 서버 OS 지정과 원격 데스크톱(RDP)

- 서버 편집 → 기본에 **서버 OS**(Linux·Windows·macOS·Unix·기타)를 추가했습니다. Windows 를 고르면 **원격 데스크톱** 탭이 생깁니다. 서버 정보와 함께 동기화됩니다(이전 버전은 새 필드를 무시합니다).
- **RDP 허용 상태 확인**: RDP 포트에 연결해 X.224 협상으로 원격 데스크톱 허용 여부, 보안 방식(NLA·TLS), 인증서 지문, 응답 시간을 보여 줍니다. 로그인은 하지 않습니다. 직접 갈 수 있는 서버는 탭을 열면 바로 확인하고, 서버 목록 우클릭 → RDP 허용 상태 확인 결과는 목록의 RDP 아이콘 색으로 표시합니다.
- **RDP 연결**: 우클릭 메뉴·행 버튼·편집 창의 "저장 후 RDP 연결"로 엽니다. "기본 연결을 RDP 로"를 켜면 더블클릭·Enter 가 원격 데스크톱을 엽니다.
  - **내장**: 앱의 별도 창에서 IronRDP(WASM)로 연결합니다. 메인 프로세스가 127.0.0.1 전용 RDCleanPath 프록시로 TCP·TLS 를 맡습니다. NLA(CredSSP)·TLS 서버를 지원하고, 서버 인증서는 처음 연결할 때 지문을 확인받아 저장합니다(바뀌면 경고). 창 크기에 맞춤(창 크기를 바꾸면 원격 화면도 바뀜) 또는 고정 해상도, Ctrl+Alt+Del·Windows 키 보내기, 전체 화면을 지원합니다.
  - **열 곳(서버별)**: 기본은 **이 창의 탭**이고 서버 편집 → 원격 데스크톱 → 열 곳에서 **별도 창**으로 바꿀 수 있습니다. 서버 목록 우클릭 메뉴로 반대쪽으로 한 번 열 수 있습니다. 원격 데스크톱 탭은 분할·패널 옮기기·모으기 대상에서 빠지고, 연결 중에 닫으면 확인합니다. 메인 창을 새로 고치면 탭 연결을 정리합니다. IronRDP 는 처음 원격 데스크톱 탭을 열 때 불러옵니다.
  - **외부 앱**: `.rdp` 파일을 만들어 Windows 는 mstsc, macOS 는 Windows App, Linux 는 `.rdp` 를 여는 앱(Remmina 등)으로 엽니다. 비밀번호는 넘기지 않습니다.
- **화질·소리·화면 설정(서버별)**: 서버 편집 → 원격 데스크톱과 RDP 화면 위 설정 버튼(슬라이더 아이콘)에서 바꿉니다. 막대에서 바꾼 값도 서버 설정에 저장됩니다.
  - 바로 적용: 화면 맞춤(맞춤·꽉 채움·실제 크기), 해상도, 배율(100~200%, Display Control), 키보드 문자 입력, 클립보드 동기화(꺼진 채 연결했으면 켜기는 다시 연결 필요).
  - 다시 연결하면 적용: 화질 프리셋(최고 화질·균형·빠르게), 색 깊이(32·24·16·15비트, 32비트는 IronRDP 값을 그대로 둠), 화면 효과 7가지(배경·테마·글꼴 다듬기·데스크톱 구성·창 끌기 내용·애니메이션·포인터 그림자), 소리. 바꾸면 "다시 연결해 적용" 버튼이 나옵니다.
  - IronRDP 웹 버전에 화질·소리 설정이 없어, 앱의 중계가 클라이언트가 보내는 Connect-Initial(TS_UD_CS_CORE 색 깊이)과 Client Info(performanceFlags·소리 비트)를 길이를 바꾸지 않고 고칩니다. 형식을 알아보지 못하면 손대지 않고 그대로 보냅니다.
  - 소리: 내장 연결은 이 PC 재생을 지원하지 않아(IronRDP 웹에 오디오 출력 없음) "원격 PC 에서 재생 / 재생 안 함"만 고릅니다. 외부 앱은 `audiomode` 로 이 PC 재생도 고를 수 있고, 화질·배율도 `.rdp` 에 넣습니다.
- **키 입력을 원격으로 그대로(macOS)**: 원격 화면에 포커스가 있으면 ⌘ 는 Windows 키로 가고(⌘ 단독 → 시작 메뉴, ⌘R → Win+R), 앱 메뉴 단축키(⌘Q·⌘W·⌘H·⌘C…)와 앱 단축키(⌘K·⌘T·⌘1…)를 끕니다. 막대에 "⌘ → ⊞ 원격 입력 중"이 보이고, 막대를 누르면 앱 단축키가 돌아옵니다.
  - macOS 시스템 단축키(⌘Tab 앱 전환·⌘Space Spotlight·⌃Space 입력 소스·Mission Control 등)는 그 창이 앞에 있고 원격 화면에 포커스가 있을 때만 끕니다. ⌘Tab 은 Win+Tab(작업 보기)으로 갑니다. 창이 뒤로 가거나 포커스가 빠지거나 앱이 끝나면 바로 되돌립니다. Moonlight·Parallels 와 같은 SkyLight `CGSSetGlobalHotKeyOperatingMode`(비공개 API)를 koffi(MIT, 2.16.3)로 부릅니다. 부를 수 없으면 ⌘Space·⌃Space·⌘⌥Space·⌃⌥Space 만 전역 단축키로 잡습니다.
  - macOS 는 ⌘ 를 누른 동안 다른 키의 keyup 을 보내지 않아, ⌘ 와 함께 누른 키는 바로 뗀 것으로 보냅니다(원격에서 키가 눌린 채 남지 않게).
- **15비트 자동 대체**: 일부 Windows(사용자 확인: Win11)는 15비트 색 깊이에서 화면 협상을 멈춥니다. 15비트로 접속해 10초 안에 로그온 정보 단계까지 못 가거나 끊기면 16비트로 자동 다시 연결하고 안내합니다. 앱을 켜 둔 동안 그 서버는 16비트로 접속하며, 저장한 설정은 15비트 그대로입니다(색 깊이를 다시 고르면 초기화). Win11 에서 16·32비트는 사용자가 접속을 확인했고, 24비트는 확인하지 않았습니다.
- **연결 진행 단계 표시**: "연결 중" 카드에 중계 단계(서버 연결 → 협상·TLS → NLA 인증 → 서버 응답 → MCS 연결 요청·도메인·사용자·채널 → 로그온 정보 → 화면 기능 교환, 끊긴 경우 주고받은 바이트)를 보입니다. 20초가 지나면 멈춘 단계에 맞는 확인 사항과 취소 버튼을 보입니다.
- **클립보드 동기화(서버별)**: 내장 창은 이 PC 와 원격의 클립보드를 양방향으로 맞춥니다(창에 포커스가 있을 때). 외부 앱에는 `.rdp` 의 `redirectclipboard` 로 넘깁니다. 운영 서버 등은 서버별로 끌 수 있습니다.
- 비밀번호: 서버 계정과 같게 / RDP 전용(볼트) / 매번 묻기. 내장 창 로그인에서 "볼트에 저장"을 고르면 RDP 전용 비밀번호로 저장합니다.
- Windows 자체 서명 RDP 인증서(keyUsage 에 digitalSignature 없음)에서 Electron(BoringSSL)이 `KEY_USAGE_BIT_INCORRECT` 로 TLS 를 끊던 문제: 이 오류가 나면 새 연결로 X.224 부터 다시 해 TLS 1.2 RSA 키 교환으로 맺습니다(허용 상태 확인·내장 연결 공통, 보안 방식에 "TLS 1.2 RSA" 표시). 같은 keyUsage 인증서의 테스트 서버로 재현·확인했고, 실제 Windows 서버는 사용자 확인이 필요합니다.
- 경로: 직접, 서버의 점프 호스트·프록시 경유, 또는 이 서버의 SSH 터널(127.0.0.1:RDP포트). 외부 앱도 이 PC 의 임시 포트로 이어 같은 경로를 씁니다.
- 검증: podman xrdp(TLS, NLA 없음)로 허용 상태 확인·인증서 확인·로그인·화면·키 입력·클립보드 양방향·서버별 끔(`test/e2e-rdp-podman.mjs`), 편집 화면·우클릭 메뉴·더블클릭 → 탭 연결·탭 닫기 확인·별도 창 열기·새로 고침 뒤 다시 연결(`test/e2e-rdp-ui.mjs`), 점프 호스트·SSH 터널 경로와 경로 SSH 연결 정리(`test/e2e-rdp-route-podman.mjs`), 16비트·효과 끔·소리 끔 접속(중계가 고쳤다는 기록과 화면 표시)·설정 패널 저장·화질 변경 후 다시 연결(32비트·저장한 해상도)(`test/e2e-rdp-options-podman.mjs`)을 자동 테스트했습니다. 접속 중 해상도 변경은 테스트용 xrdp(0.9.24)에 반영되지 않아 확인하지 못했고, 배율·소리·화면 효과가 실제 Windows 에 적용되는지도 확인하지 않았습니다. e2e 테스트는 연결이 남아 있어도 종료 확인 창 없이 닫습니다(`test/close-app.mjs`). 15비트 대체는 xrdp 가 15비트를 정상 처리해 테스트용 지연(`BT_TEST_RDP_STALL_DEPTH=15`)으로 확인했습니다. 시스템 단축키 끄기는 앱 프로세스의 모드 값(0↔1)과 패키지(arm64)의 koffi 로드까지 확인했고, 실제 ⌘Tab·⌘Space 키 입력은 사용자 확인이 필요합니다. **실제 Windows(NLA·CredSSP) 서버와 외부 앱 실행(mstsc·Windows App·Remmina)은 아직 검증하지 않았습니다.** xrdp 로그인 창 등 일부 비트맵이 비스듬히 그려지는 IronRDP 표시 문제를 확인했습니다.

### Git 동기화 문제 말풍선 알림

- 우측 동기화 아이콘 아래에 실패·충돌·원격 볼트 비밀번호 확인 필요 상태를 말풍선으로 알립니다. 원인 메시지와 설정으로 이동하는 버튼을 제공합니다.
- 알림은 터미널의 키보드 포커스를 가져가지 않습니다. 닫은 뒤 같은 오류의 자동 재시도가 반복돼도 다시 띄우지 않고, 정상 복구 후 새로 발생하거나 원인·저장소가 바뀌면 알립니다.
- 충돌 화면의 **차이 미리보기**에서 서버·폴더·스니펫·계정·볼트 정보의 차이와 양쪽 값을 확인할 수 있습니다. 비밀번호·개인 키는 메인 프로세스에서 비교하고 값은 표시하지 않습니다.
- 비교 후 로컬·원격·설정이 바뀌거나 볼트가 잠기면 이전 결과로 적용하지 않습니다. 미리보기는 5분간 유효하며, 조회만으로 데이터를 변경하거나 업로드하지 않습니다. [사용 방법과 검증 범위](git-sync-conflict-preview.md)를 참고하세요.

### 데스크톱 마우스 보고 정리 및 서버별 차단

- 연결 상태가 바뀌어 끊기거나 재접속할 때 이전 프로그램의 마우스 모드를 해제합니다. 기존 화면·스크롤 기록은 유지합니다.
- 서버 편집 → 터미널에 **서버 프로그램에 마우스 입력 전달** 옵션을 추가했습니다. 기본 허용이며, 끄면 열린 연결에도 적용되고 프로그램의 마우스 모드 재요청·보고 전송·대체 화면 휠 방향키 입력을 차단합니다. 서버 정보와 함께 동기화됩니다.
- 마우스 보고는 해당 연결에만 전송하고 다른 패널에 브로드캐스트하지 않습니다.
- 공통 확인창 하단 버튼을 좌우 방향키로 이동할 수 있습니다. 양 끝에서 순환하며 Enter로 실행합니다. 위험 동작의 초기 선택은 취소로 유지합니다.

## 1.3.0 — BrightTerm Extended (2026-11-11)

- 독립 포크의 제품명을 **BrightTerm Extended**, 데스크톱·Android 버전을 **1.3.0**으로 변경했습니다. 원본 BrightTerm 1.3.0을 병합한 버전은 아닙니다.
- 앱 제목·시작 화면·정보 화면·설치 파일의 이름을 변경하고 비공식 포크임을 표시합니다. 정보 화면에서 원본 프로젝트를 확인할 수 있습니다.
- 새 버전 알림은 `dearmai/BrightTerm` 릴리스를 확인합니다.
- 기존 앱 식별자·데스크톱 `BrightTerm` 데이터 경로·포터블 `BrightTerm-data` 경로·Git 동기화 형식은 유지합니다. Android는 기존 패키지 ID를 유지하고 versionCode를 3으로 올렸습니다.

아래 기능은 원본 1.2.3 이후 이 포크에서 추가한 변경입니다.

### tmux 마우스 모드 적용 수정

- 최초 접속·재접속 때 마우스 모드가 켜짐으로 표시되어도 실제로 적용되지 않아 휠이 이전 명령어를 불러오던 문제를 수정했습니다. 데스크톱과 Android의 tmux 대상 지정을 수정했습니다.
- 같은 원인으로 실패하던 자동 실행 명령 전송도 수정했습니다. 마우스 모드 적용 오류는 터미널에 표시합니다.

### 접속 상세 로그

탭 제목 우클릭(Android는 길게 터치) → **접속 상세 로그**에서 `ssh -v`·`-vv`에 해당하는 알고리즘 협상·인증·끊김 과정과 오류 원문을 볼 수 있습니다. 접속할 때부터 자동으로 모으며, 비밀번호·키와 터미널 입출력은 기록하지 않습니다. 메모리에만 있고 탭을 닫으면 사라집니다.

### 서버 OS·쉘 매뉴얼 (우측 패널)

우측 패널의 **매뉴얼** 탭에서 AIX 7.2–7.3, RHEL 9, RHEL 10, ksh, bash, zsh 문서를 볼 수 있습니다. 문서는 앱에 포함되어 있어 인터넷 없이 열리고, 문서 안에서 찾기와 코드 복사를 지원합니다.

- SSH 세션은 탭을 열 때 별도 명령 채널로 `uname`, `/etc/os-release`, `$SHELL`을 확인해 맞는 문서를 먼저 보여 줍니다. 터미널에는 아무것도 입력하지 않습니다.
- Rocky Linux·AlmaLinux 같은 RHEL 호환 배포판에는 같은 메이저 버전의 RHEL 문서를 보여 줍니다.
- 텔넷·시리얼 세션이나 확인에 실패한 서버는 문서를 직접 고릅니다.

### 스니펫 동기화 및 가져오기·내보내기

- 스니펫을 Git 동기화에 포함합니다(볼트와 같이 암호화). 업데이트 후 처음 동기화할 때는 기기마다 있던 스니펫을 합칩니다. 모든 데스크톱을 새 버전으로 올려 주세요. 이전 버전이 동기화하면 원격에서 스니펫이 빠졌다가, 새 버전이 다시 올립니다.
- 스니펫 패널에서 JSON 파일로 내보내고 가져올 수 있습니다. 가져오기는 기존 스니펫을 바꾸지 않습니다. 내보낸 파일은 암호화되지 않습니다.
- Android 는 스니펫을 표시하지 않지만 동기화 데이터에는 보존합니다.

### 터미널 테마를 탭 우클릭 메뉴에서 변경

접속한 서버의 터미널 테마를 패널 머리말의 드롭다운 대신 탭 타이틀 우클릭 메뉴에서 고릅니다. 탭에 패널이 여럿이면 모든 패널에 적용됩니다. 분할한 패널을 하나만 바꾸려면 그 패널의 우클릭 메뉴를 씁니다(터미널 영역에서는 우클릭 붙여넣기가 켜져 있으면 머리말이나 Shift+우클릭).

### 빌드 번호 표시 (데스크톱)

설정 → 정보와 macOS의 BrightTerm 정보 창에서 `1.2.3_20261105_1`(버전_날짜_순번) 형식의 빌드 번호를 확인할 수 있습니다. 순번은 빌드한 PC에서 같은 버전·같은 날 빌드할 때마다 1씩 늘어납니다. 개발 실행(`npm run dev`)은 `1.2.3_dev`로 표시됩니다. 패키지 파일 이름과 새 버전 확인에 쓰는 버전은 그대로입니다.

### 유휴 방지 명령 (TMOUT 대응)

서버 편집 → 고급에서 켜면 셸 프롬프트에 입력이 없을 때 지정한 간격마다 명령(기본 `date`)을 보냅니다(SSH·텔넷, 데스크톱). Keepalive 는 연결만 유지해 셸의 `TMOUT` 을 막지 못하기 때문입니다. vi·less 실행 중, 입력하던 줄이 있을 때, `SQL>` 처럼 셸이 아닌 프롬프트에서는 보내지 않고, ksh 의 `shell will time out` 경고가 보이면 바로 보냅니다.

### 서버별 자동 재접속 설정

서버 편집 → 고급에서 **끊기면 자동 재접속**을 앱 설정 따르기·켜기·끄기 중에 고릅니다(SSH·텔넷, 데스크톱). 기본값은 앱 설정 따르기이므로 기존 서버의 동작은 바뀌지 않습니다. 접속 중에 바꿔도 다음 끊김부터 적용되며, 값은 Git 동기화로 함께 전달됩니다.

### Linux ARM64 deb 빌드 및 PRoot 실행 안내

- `make deb ARCH=arm64`, `npm run dist:linux:deb:arm64`로 ARM64 deb를 빌드할 수 있습니다. x64 Linux 교차 빌드에 필요한 컴파일러와 사용법을 README에 추가했습니다.
- 패키지의 `node-pty` 바이너리 아키텍처를 확인하고 필요하면 대상 아키텍처로 빌드합니다. 개발용 호스트 모듈은 유지합니다.
- PRoot-Distro에서 기본 실행이 종료되는 경우 사용자가 확인한 `--no-sandbox` 실행법을 안내합니다. 일반 Linux의 실행 기본값은 유지합니다.

### 포터블 버전은 실행 파일 옆에 설정 저장 (Windows)

`BrightTerm-Portable-*.exe`는 설정·볼트·창 위치·Git 동기화·세션 로그를 실행 파일과 같은 폴더의 `BrightTerm-data\`에 저장합니다. exe 와 폴더를 함께 USB 등으로 옮기면 설정도 따라갑니다.

- 처음 실행할 때 `%APPDATA%\BrightTerm`에 쓰던 데이터가 있으면 로그를 빼고 복사해 옵니다.
- 실행 파일 위치에 쓸 수 없으면(읽기 전용 매체, Program Files 등) 예전처럼 `%APPDATA%`를 씁니다.
- 설치형과 데이터가 따로라서 두 버전을 동시에 띄울 수 있습니다.
- 다른 PC 로 옮기면 Windows 잠금 해제는 동작하지 않으므로 마스터 비밀번호로 엽니다.

### Windows 코드 서명 (셀프 인증서, 사내 배포용)

사내·폐쇄망 배포용으로 자체 발급 인증서로 서명하는 빌드를 추가했습니다.

1. 처음 한 번 `scripts\codesign-cert.ps1`을 실행합니다. 코드 서명 인증서를 현재 사용자 인증서 저장소에 만들고, 공개 인증서를 `build\codesign\BrightTerm-codesign.cer`로 내보냅니다. `-BackupPfx <경로>`를 주면 개인 키를 비밀번호 걸린 파일로 백업합니다.
2. `npm run dist:win:signed`로 빌드합니다. 설치형·포터블과 그 안의 실행 파일을 SHA-256 으로 서명하고 DigiCert 타임스탬프를 넣습니다. 그래서 인증서가 만료돼도 서명은 유효합니다.
3. 배포 대상 PC 에서 `build\codesign\install-cert.cmd`를 실행하거나 GPO 로 `.cer`를 배포합니다. 인증서는 신뢰할 수 있는 루트 인증 기관과 신뢰할 수 있는 게시자 두 곳에 등록됩니다. 그러면 '확인된 게시자: Dany Kim'으로 보이고, 게시자 기준 실행 정책(AppLocker·WDAC)에도 쓸 수 있습니다.

- 개인 키와 비밀번호는 설정 파일이나 저장소에 두지 않습니다. 서명할 때 인증서 저장소에서 주체 이름으로 찾습니다.
- 셀프 인증서라 SmartScreen 평판은 생기지 않습니다. 일반 배포는 지금처럼 `npm run dist:win`을 씁니다.
- 개인 키 보관·백업·복원·분실·유출·갱신 절차는 [코드 서명 문서](./codesign.md)에 있습니다.

### 프록시를 거쳐 접속 (HTTP · HTTPS · SOCKS5 · SOCKS4)

회사망처럼 서버로 바로 나갈 수 없는 곳에서 프록시를 거쳐 SSH·텔넷 서버에 접속할 수 있습니다. 새 의존성 없이 직접 구현했습니다.

- 서버 편집 → **고급** → **프록시**에서 종류, 주소, 포트, 사용자 이름(선택), 비밀번호를 정합니다.
- 주소 칸에 `socks5://user:pass@host:1080`, `https://proxy.corp:8443` 같은 주소를 붙여 넣으면 칸이 나뉘어 채워집니다.

| 종류 | 방식 | 기본 포트 |
| --- | --- | --- |
| SOCKS5 | 인증 없음 또는 사용자 이름·비밀번호. 서버 주소 이름 풀기도 프록시가 합니다(socks5h 와 같음) | 1080 |
| HTTP | `CONNECT` 터널. 사용자 이름이 있으면 Basic 인증 | 8080 |
| HTTPS | 프록시까지 TLS 로 암호화하고 그 안에서 `CONNECT` | 443 |
| SOCKS4 | SOCKS4a — 주소 이름 풀기는 프록시가. 비밀번호 인증 없음 | 1080 |

- **인증은 선택**입니다. 사용자 이름을 비우면 인증 없이 접속합니다(사내 프록시 등). 비밀번호는 볼트에 암호화해 저장하고, 서버 목록·Git 동기화에는 사용자 이름까지만 들어갑니다.
- HTTPS 프록시는 **인증서 확인 건너뛰기**를 켤 수 있습니다(기본 꺼짐). 사내 자체 서명 인증서용이며, 인증서를 확인하지 못해 실패하면 이 옵션을 안내합니다. SSH 서버 자체는 이와 상관없이 호스트 키로 확인합니다.
- 점프 호스트를 쓰면 이 PC 에서 첫 번째 베스천으로 갈 때 프록시를 거칩니다. 등록된 점프 호스트에 프록시가 따로 있으면 그것을 씁니다.
- SFTP, 서버 확인(tmux), SSH 키 등록도 같은 연결이라 프록시를 거칩니다.
- 접속 중 터미널에 `프록시 SOCKS5 127.0.0.1:1080 경유 중...`을 보여 주고, 인증 요구·인증 실패·연결 거부 등은 이유를 한국어로 알려 줍니다.

### 탭을 서버 묶음처럼 — 패널을 탭 사이로 옮기기

한 탭에 여러 서버를 패널로 모아 두고, 패널을 다른 탭이나 새 탭으로 옮길 수 있습니다. 옮기는 동안 연결·화면·스크롤 기록·tmux 세션은 그대로입니다.

- **끌어서 놓기**
  - 탭을 끌어 패널 위에 놓으면 그 탭의 패널(배치 전체)이 마우스에 가까운 가장자리(왼쪽·오른쪽·위·아래)에 붙고 원래 탭은 없어집니다. 놓일 자리는 반투명 영역으로 미리 보입니다.
  - 패널 머리(제목 줄)를 끌어 다른 패널 옆에 놓으면 그 자리로 옮겨집니다. 같은 탭 안에서 자리를 바꾸는 것도 됩니다.
  - 패널을 탭 머리에 놓으면 그 탭의 오른쪽 끝에 붙습니다.
  - 패널을 끄는 동안 `+` 자리에 **새 탭으로** 칸이 나타납니다. 여기에 놓으면 그 패널이 자기 탭으로 떨어집니다.
  - 끌면서 다른 탭 머리 위에 잠깐(0.6초) 머무르면 그 탭이 열려서, 그 탭의 패널 옆에 놓을 수 있습니다.
  - 탭을 탭 머리에 놓으면 예전처럼 순서만 바뀝니다.
- **메뉴**
  - 탭 우클릭 → **다른 탭에 패널로 넣기** 아래의 탭 목록
  - 패널 우클릭 → **새 탭으로 분리**, **다른 탭으로 옮기기** 아래의 탭 목록
- 탭 이름은 직접 지은 이름이 있으면 그 이름, 없으면 포커스된 패널의 서버 이름입니다. 서버 묶음으로 쓸 때는 탭 이름을 바꿔 두면 됩니다.

### 서버 연결을 닫을 때 확인

- 서버에 연결된 패널을 닫으면 확인 창이 뜹니다(X 버튼, 우클릭 메뉴, 단축키 모두). 연결이 끊긴 창과 로컬 터미널은 묻지 않습니다.
- 탭 닫기는 연결이 하나만 있어도 묻습니다(예전에는 둘 이상일 때만). 탭의 패널마다 따로 묻지 않고 한 번만 묻습니다.
- **다른 탭 모두 닫기**도 다른 탭들의 연결 수를 모아 한 번 묻습니다(예전에는 묻지 않음).
- 닫는 창이 tmux 세션에 붙어 있으면 버튼이 셋입니다.

| 버튼 | 동작 |
| --- | --- |
| 유지하고 닫기 | 연결만 끊습니다. 안의 프로그램은 계속 돌고 다시 열면 그대로 붙습니다 |
| 세션 끝내기 | 서버의 tmux 세션과 안의 프로그램까지 끝냅니다(`tmux kill-session`, 응답이 없으면 5초 뒤 그냥 닫음) |
| 취소 | 닫지 않습니다. 처음 포커스가 여기 있어 Enter 를 잘못 눌러도 닫히지 않습니다 |

- 앱 종료 확인도 tmux 세션이 있으면 **tmux 세션 유지하고 종료** / **tmux 세션도 끝내고 종료** / **취소** 중에서 고릅니다.

### 세션 유지 서버에 일반 접속

- 사이드바 서버 우클릭 → **세션 유지 없이 연결 (일반 접속)**: 서버 설정은 그대로 두고 이번 창만 tmux 없이 엽니다. 자동 실행 명령은 평소처럼 실행됩니다. 세션 유지가 켜진 SSH 서버와 로컬 터미널에만 보입니다.
- 이어 쓸 세션 선택 창에 **일반 접속 (세션 유지 안 함)** 항목을 더했습니다.
- 일반 접속으로 연 창은 자동 재접속, 같은 서버 분할·복제, 앱을 다시 켤 때 탭 복원에서도 일반 접속으로 열립니다.

### tmux 마우스 모드 정하기

tmux 의 `mouse on` 상태에서는 드래그로 잡은 블록이 손을 떼자마자 풀립니다(tmux 기본 동작: 복사 후 복사 모드 종료). 이 모드를 서버별로, 또 접속 중에도 바꿀 수 있게 했습니다.

- 서버 편집 → 세션 유지 → **tmux 마우스 모드** (기본 켜짐 — 예전과 같음). 이제 새 세션을 만들 때만이 아니라 **붙을 때마다** 이 값으로 맞춥니다.
- 패널 우클릭 → **tmux 마우스 모드 끄기/켜기**: 지금 붙어 있는 tmux 세션에 바로 적용합니다. 그 창이 다시 접속할 때도 바꾼 값을 씁니다(서버 설정은 바뀌지 않음).
- 끄면 드래그 선택이 유지되고, 마우스 휠은 tmux 스크롤 대신 위·아래 키로 보냅니다. 켠 상태에서도 Shift+드래그(macOS ⌥+드래그)로는 블록이 유지됩니다.
- 마우스 모드는 tmux 세션 단위라, 같은 세션을 함께 보는 다른 창에도 적용됩니다.
- 로컬 세션 유지 창은 이 PC 의 tmux(Windows 는 WSL 안의 tmux)에 적용합니다.

### 고친 문제

- 접속하는 동안(tmux 세션 고르기 등) 창 크기가 바뀌면 서버에 전달되지 않아 tmux·btop 등이 120×32 기본 크기로 그려지던 문제. 접속이 끝나면 지금 창 크기를 다시 보냅니다.

### 세션 유지(tmux) — 이어 쓸 세션 고르기

같은 서버를 분할로 두 번 열면 두 창이 한 tmux 세션에 붙어 똑같은 화면을 보여 주던 문제를 고치면서, 접속할 때 어느 세션에 붙을지 고를 수 있게 했습니다.

- 세션 유지가 켜진 **SSH 서버**에 접속하면 셸을 열기 전에 그 서버의 tmux 세션 목록을 봅니다. 그 서버의 세션은 `bt-<별칭>`과 새로 만든 `bt-<별칭>-2`, `-3` …입니다(tmux 세션 이름을 정했으면 그 이름이 기준).
- 이전 세션이 있으면 **선택 창**이 뜹니다.
  - 세션마다 실행 중인 프로그램, 마지막 활동, 만든 때를 보여 줍니다.
  - 다른 창(이 앱이나 다른 PC)에서 보고 있는 세션은 **다른 창에서 사용 중**으로 표시합니다.
  - 기본 선택은 아무도 보고 있지 않은 최근 세션입니다. 모두 사용 중이면 **새 세션**이 선택됩니다.
  - 🗑 로 세션을 끝낼 수 있습니다(`tmux kill-session`, 확인 후).
  - 취소하면 접속하지 않습니다. Enter 로 다시 시도할 수 있습니다.
- 이전 세션이 없으면 묻지 않고 새로 만듭니다.
- 묻지 않는 경우:

| 상황 | 붙는 세션 |
| --- | --- |
| 연결이 끊겨 자동 재접속 | 그 창이 쓰던 세션 |
| 앱을 다시 켜 탭·분할 복원 | 그 창이 쓰던 세션(세션 이름을 작업 공간에 함께 저장). 이전 버전에서 저장한 배치는 쉬는 세션 |
| 폴더 전체를 그리드로 열기 | 서버마다 아무도 보고 있지 않은 최근 세션, 없으면 새 세션 |

- 창 머리의 **유지** 표시에 세션 번호가 붙습니다(예: `유지 2`). 마우스를 올리면 세션 이름이 보입니다.
- 로컬 터미널(macOS·Linux·WSL)은 예전처럼 세션 하나에 바로 붙습니다.

### 세션 유지 — 서버 확인과 tmux 설치

- 서버 편집의 세션 유지 옆 **서버 확인**: 접속해서 tmux 버전, 배포판, root·sudo 여부, 패키지 관리자를 확인합니다. 저장하기 전 설정으로도 확인할 수 있습니다.
- tmux 가 없으면 배포판에 맞는 설치 명령을 보여 줍니다.

| 패키지 관리자 | 설치 명령 (root 가 아니면 앞에 `sudo`) |
| --- | --- |
| apt | `apt-get update && apt-get install -y tmux` |
| dnf / yum | `dnf install -y tmux` / `yum install -y tmux` |
| zypper | `zypper --non-interactive install tmux` |
| apk | `apk add tmux` |
| pacman | `pacman -S --noconfirm tmux` |
| brew (macOS) | `brew install tmux` |

- **저장하고 터미널에서 설치**: 서버를 저장하고 새 탭에서 접속해 설치 명령을 입력해 줍니다. 이 탭은 세션 유지 없이 열리며, sudo 비밀번호는 터미널에서 직접 입력합니다. 앱이 sudo 비밀번호를 받거나 저장하지 않습니다. **복사** 버튼도 있습니다.
- root 도 아니고 sudo 도 없는 계정이면 서버 관리자에게 설치를 요청하도록 안내합니다.
- 접속했는데 서버에 tmux 가 없으면 터미널에 서버 확인 메뉴를 안내합니다.

### 세션 유지 — 찾기 쉽게

- 세션 유지 스위치를 서버 편집 **고급** 탭에서 **기본** 탭으로 옮겼습니다.
- 사이드바에서 세션 유지가 켜진 서버 이름 옆에 겹친 네모 아이콘을 표시합니다.

### SSH 키 등록

비밀번호로 로그인하는 서버에 이 PC 의 공개키를 등록합니다(`ssh-copy-id` 와 같은 일).

- 대상: 인증 방식이 **비밀번호** 또는 **매번 묻기**인 SSH 서버. 사이드바 항목에 마우스를 올리면 🔑 버튼이, 우클릭 메뉴에 **SSH 키 등록…**이 나옵니다.
- 등록하기 전에 `~/.ssh/*.pub` 목록에서 키를 고릅니다. 파일 이름, 종류, 주석, SHA256 지문과 어느 서버(`user@host`)의 `~/.ssh/authorized_keys` 에 넣을지 보여 줍니다.
  - ed25519 → ecdsa → rsa 순으로 정렬하고 첫 키를 미리 고릅니다.
  - 짝이 되는 개인 키가 없는 `.pub` 은 **개인 키 없음**으로 표시합니다(등록해도 이 PC 에서는 그 키로 로그인할 수 없음).
- 접속은 평소와 같습니다. 저장된 비밀번호를 쓰고, 없으면 묻고, 호스트 키 확인과 점프 호스트도 그대로 거칩니다.
- **이미 등록된 키면 아무것도 바꾸지 않습니다.** 주석이 다르거나 앞에 `from="..."` 같은 옵션이 붙어 있어도 키 본문이 같으면 같은 키로 봅니다.
- 서버에 `~/.ssh` 나 `authorized_keys` 가 없으면 권한 700/600 으로 만들고, 파일 끝에 줄바꿈이 없으면 보충해 마지막 키와 붙지 않게 합니다. SELinux 서버는 `restorecon` 으로 보안 문맥을 맞춥니다.
- 등록한 뒤에도 서버 설정은 비밀번호 로그인 그대로입니다.

### 터미널 링크 열기 (OSC 8 · 일반 주소)

Claude Code 의 `/login` 주소처럼 프로그램이 링크로 출력한 주소(OSC 8 하이퍼링크)를 눌러 확인해도 브라우저가 열리지 않던 문제를 고쳤습니다. 화면에 그냥 찍힌 `https://…` 주소도 마우스를 올리면 링크로 보이지만 Ctrl+클릭으로만 열려서, 그냥 클릭하면 반응이 없었습니다. 이제 두 경우가 똑같이 동작합니다.

- 그냥 클릭: 앱 확인 창에 **주소 전체**를 보여 주고 **열기**를 누르면 기본 브라우저로 엽니다. OSC 8 링크는 보이는 글자와 실제 주소가 다를 수 있어서 확인합니다.
- Ctrl+클릭(macOS ⌘+클릭): 묻지 않고 바로 엽니다.
- `(https://…)`처럼 괄호로 감싼 주소는 괄호를 빼고 엽니다.
- `http`/`https` 주소만 엽니다.

### Windows 계정 잠금 해제 기본 켜기

- Windows 에서 처음 볼트를 만들 때 **Windows 계정으로 잠금 해제** 체크가 기본으로 켜져 있습니다. 볼트 키를 `safeStorage`(DPAPI)로 암호화해 이 PC 에만 보관하고, 앱을 켜면 자동으로 잠금이 풀립니다. Git 동기화·백업에는 들어가지 않습니다.
- 체크를 풀고 만들 수 있고, 나중에 **설정 → 보안·계정**에서 켜고 끌 수 있습니다.
- 이미 만든 볼트의 설정은 바꾸지 않습니다.

### 서버 쪽 동작 메모 (개발용)

- 서버에서 실행하는 스크립트(키 등록, tmux 목록, 서버 확인)는 `sh -s` 표준입력으로 보냅니다. 로그인 셸이 fish·csh 여도 되지만 `sh` 가 없는 서버(Windows OpenSSH 등)에서는 실패하고 오류를 보여 줍니다.

## 차후 과제

### Windows Hello 로 볼트 잠금 해제 확인

- 현재: Windows 에서 **설정 → 보안·계정 → Windows 계정으로 잠금 해제**를 켜면 볼트 키를 Electron `safeStorage`(DPAPI)로 암호화해 이 PC 에만 보관합니다(Git 동기화·백업에는 들어가지 않음). 같은 Windows 계정으로 로그인해 있으면 **추가 확인 없이** 열립니다.
- 목표: macOS 의 Touch ID 처럼, `safeStorage` 로 볼트 키를 꺼내기 전에 Windows Hello(PIN·지문·얼굴) 확인을 받습니다. 확인을 취소하거나 Hello 를 쓸 수 없으면 마스터 비밀번호로 엽니다.
- 방법 후보: Electron 에 Windows Hello API 가 없으므로 WinRT `Windows.Security.Credentials.UI.UserConsentVerifier`(`CheckAvailabilityAsync`, `RequestVerificationAsync`)를 부릅니다.
  - PowerShell 로 호출: 추가 모듈이 필요 없지만 PowerShell 시작에 1~2초가 걸리고, 확인 창이 앱 창 뒤에 뜨지 않게 처리해야 합니다.
  - 네이티브 모듈: 빠르고 창 연결이 자연스럽지만 빌드·서명 대상이 늘어납니다.
- 관련 코드: `src/main/vault.ts` 의 `tryOsUnlock`(macOS 는 여기서 `promptTouchID`), 설정 문구는 `src/renderer/src/platform.ts` 의 `osUnlockText`.
