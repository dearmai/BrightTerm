# 변경 내역

## 다음 버전 (미배포, 1.2.3 이후)

### 포터블 버전은 실행 파일 옆에 설정 저장 (Windows)

`BrightTerm-Portable-*.exe`는 설정·볼트·창 위치·Git 동기화·세션 로그를 실행 파일과 같은 폴더의 `BrightTerm-data\`에 저장합니다. exe 와 폴더를 함께 USB 등으로 옮기면 설정도 따라갑니다.

- 처음 실행할 때 `%APPDATA%\BrightTerm`에 쓰던 데이터가 있으면 로그를 빼고 복사해 옵니다.
- 실행 파일 위치에 쓸 수 없으면(읽기 전용 매체, Program Files 등) 예전처럼 `%APPDATA%`를 씁니다.
- 설치형과 데이터가 따로라서 두 버전을 동시에 띄울 수 있습니다.
- 다른 PC 로 옮기면 Windows 잠금 해제는 동작하지 않으므로 마스터 비밀번호로 엽니다.

### Windows 코드 서명 (셀프 인증서, 사내 배포용)

사내·폐쇄망 배포용으로 자체 발급 인증서로 서명하는 빌드를 추가했습니다.

1. 처음 한 번 `scripts\codesign-cert.ps1`을 실행합니다. 코드 서명 인증서를 현재 사용자 인증서 저장소에 만들고, 공개 인증서를 `build\codesign\BrightTerm-codesign.cer`로 내보냅니다. `-BackupPfx <경로>`를 주면 개인 키를 비밀번호 걸린 파일로 백업합니다.
2. `npm run dist:win:signed`로 빌드합니다. 설치형·포터블과 그 안의 실행 파일을 SHA-256 으로 서명하고 DigiCert 타임스탬프를 넣습니다. 그래서 인증서가 만료돼도 서명은 유효합니다.
3. 배포 대상 PC 에서 `build\codesign\install-cert.cmd`를 실행하거나 GPO 로 `.cer`를 배포합니다. 인증서는 신뢰할 수 있는 루트 인증 기관과 신뢰할 수 있는 게시자 두 곳에 등록됩니다. 그러면 '확인된 게시자: Dany Kim'으로 보이고, 게시자 기준 실행 정책(AppLocker·WDAC)에도 쓸 수 있습니다.

- 개인 키와 비밀번호는 설정 파일이나 저장소에 두지 않습니다. 서명할 때 인증서 저장소에서 주체 이름으로 찾습니다.
- 셀프 인증서라 SmartScreen 평판은 생기지 않습니다. 일반 배포는 지금처럼 `npm run dist:win`을 씁니다.
- 개인 키 보관·백업·복원·분실·유출·갱신 절차는 [코드 서명 문서](./codesign.md)에 있습니다.

### 프록시를 거쳐 접속 (HTTP · HTTPS · SOCKS5 · SOCKS4)

회사망처럼 서버로 바로 나갈 수 없는 곳에서 프록시를 거쳐 SSH·텔넷 서버에 접속할 수 있습니다. 새 의존성 없이 직접 구현했습니다.

- 서버 편집 → **고급** → **프록시**에서 종류, 주소, 포트, 사용자 이름(선택), 비밀번호를 정합니다.
- 주소 칸에 `socks5://user:pass@host:1080`, `https://proxy.corp:8443` 같은 주소를 붙여 넣으면 칸이 나뉘어 채워집니다.

| 종류 | 방식 | 기본 포트 |
| --- | --- | --- |
| SOCKS5 | 인증 없음 또는 사용자 이름·비밀번호. 서버 주소 이름 풀기도 프록시가 합니다(socks5h 와 같음) | 1080 |
| HTTP | `CONNECT` 터널. 사용자 이름이 있으면 Basic 인증 | 8080 |
| HTTPS | 프록시까지 TLS 로 암호화하고 그 안에서 `CONNECT` | 443 |
| SOCKS4 | SOCKS4a — 주소 이름 풀기는 프록시가. 비밀번호 인증 없음 | 1080 |

- **인증은 선택**입니다. 사용자 이름을 비우면 인증 없이 접속합니다(사내 프록시 등). 비밀번호는 볼트에 암호화해 저장하고, 서버 목록·Git 동기화에는 사용자 이름까지만 들어갑니다.
- HTTPS 프록시는 **인증서 확인 건너뛰기**를 켤 수 있습니다(기본 꺼짐). 사내 자체 서명 인증서용이며, 인증서를 확인하지 못해 실패하면 이 옵션을 안내합니다. SSH 서버 자체는 이와 상관없이 호스트 키로 확인합니다.
- 점프 호스트를 쓰면 이 PC 에서 첫 번째 베스천으로 갈 때 프록시를 거칩니다. 등록된 점프 호스트에 프록시가 따로 있으면 그것을 씁니다.
- SFTP, 서버 확인(tmux), SSH 키 등록도 같은 연결이라 프록시를 거칩니다.
- 접속 중 터미널에 `프록시 SOCKS5 127.0.0.1:1080 경유 중...`을 보여 주고, 인증 요구·인증 실패·연결 거부 등은 이유를 한국어로 알려 줍니다.

### 탭을 서버 묶음처럼 — 패널을 탭 사이로 옮기기

한 탭에 여러 서버를 패널로 모아 두고, 패널을 다른 탭이나 새 탭으로 옮길 수 있습니다. 옮기는 동안 연결·화면·스크롤 기록·tmux 세션은 그대로입니다.

- **끌어서 놓기**
  - 탭을 끌어 패널 위에 놓으면 그 탭의 패널(배치 전체)이 마우스에 가까운 가장자리(왼쪽·오른쪽·위·아래)에 붙고 원래 탭은 없어집니다. 놓일 자리는 반투명 영역으로 미리 보입니다.
  - 패널 머리(제목 줄)를 끌어 다른 패널 옆에 놓으면 그 자리로 옮겨집니다. 같은 탭 안에서 자리를 바꾸는 것도 됩니다.
  - 패널을 탭 머리에 놓으면 그 탭의 오른쪽 끝에 붙습니다.
  - 패널을 끄는 동안 `+` 자리에 **새 탭으로** 칸이 나타납니다. 여기에 놓으면 그 패널이 자기 탭으로 떨어집니다.
  - 끌면서 다른 탭 머리 위에 잠깐(0.6초) 머무르면 그 탭이 열려서, 그 탭의 패널 옆에 놓을 수 있습니다.
  - 탭을 탭 머리에 놓으면 예전처럼 순서만 바뀝니다.
- **메뉴**
  - 탭 우클릭 → **다른 탭에 패널로 넣기** 아래의 탭 목록
  - 패널 우클릭 → **새 탭으로 분리**, **다른 탭으로 옮기기** 아래의 탭 목록
- 탭 이름은 직접 지은 이름이 있으면 그 이름, 없으면 포커스된 패널의 서버 이름입니다. 서버 묶음으로 쓸 때는 탭 이름을 바꿔 두면 됩니다.

### 서버 연결을 닫을 때 확인

- 서버에 연결된 패널을 닫으면 확인 창이 뜹니다(X 버튼, 우클릭 메뉴, 단축키 모두). 연결이 끊긴 창과 로컬 터미널은 묻지 않습니다.
- 탭 닫기는 연결이 하나만 있어도 묻습니다(예전에는 둘 이상일 때만). 탭의 패널마다 따로 묻지 않고 한 번만 묻습니다.
- **다른 탭 모두 닫기**도 다른 탭들의 연결 수를 모아 한 번 묻습니다(예전에는 묻지 않음).
- 닫는 창이 tmux 세션에 붙어 있으면 버튼이 셋입니다.

| 버튼 | 동작 |
| --- | --- |
| 유지하고 닫기 | 연결만 끊습니다. 안의 프로그램은 계속 돌고 다시 열면 그대로 붙습니다 |
| 세션 끝내기 | 서버의 tmux 세션과 안의 프로그램까지 끝냅니다(`tmux kill-session`, 응답이 없으면 5초 뒤 그냥 닫음) |
| 취소 | 닫지 않습니다. 처음 포커스가 여기 있어 Enter 를 잘못 눌러도 닫히지 않습니다 |

- 앱 종료 확인도 tmux 세션이 있으면 **tmux 세션 유지하고 종료** / **tmux 세션도 끝내고 종료** / **취소** 중에서 고릅니다.

### 세션 유지 서버에 일반 접속

- 사이드바 서버 우클릭 → **세션 유지 없이 연결 (일반 접속)**: 서버 설정은 그대로 두고 이번 창만 tmux 없이 엽니다. 자동 실행 명령은 평소처럼 실행됩니다. 세션 유지가 켜진 SSH 서버와 로컬 터미널에만 보입니다.
- 이어 쓸 세션 선택 창에 **일반 접속 (세션 유지 안 함)** 항목을 더했습니다.
- 일반 접속으로 연 창은 자동 재접속, 같은 서버 분할·복제, 앱을 다시 켤 때 탭 복원에서도 일반 접속으로 열립니다.

### tmux 마우스 모드 정하기

tmux 의 `mouse on` 상태에서는 드래그로 잡은 블록이 손을 떼자마자 풀립니다(tmux 기본 동작: 복사 후 복사 모드 종료). 이 모드를 서버별로, 또 접속 중에도 바꿀 수 있게 했습니다.

- 서버 편집 → 세션 유지 → **tmux 마우스 모드** (기본 켜짐 — 예전과 같음). 이제 새 세션을 만들 때만이 아니라 **붙을 때마다** 이 값으로 맞춥니다.
- 패널 우클릭 → **tmux 마우스 모드 끄기/켜기**: 지금 붙어 있는 tmux 세션에 바로 적용합니다. 그 창이 다시 접속할 때도 바꾼 값을 씁니다(서버 설정은 바뀌지 않음).
- 끄면 드래그 선택이 유지되고, 마우스 휠은 tmux 스크롤 대신 위·아래 키로 보냅니다. 켠 상태에서도 Shift+드래그(macOS ⌥+드래그)로는 블록이 유지됩니다.
- 마우스 모드는 tmux 세션 단위라, 같은 세션을 함께 보는 다른 창에도 적용됩니다.
- 로컬 세션 유지 창은 이 PC 의 tmux(Windows 는 WSL 안의 tmux)에 적용합니다.

### 고친 문제

- 접속하는 동안(tmux 세션 고르기 등) 창 크기가 바뀌면 서버에 전달되지 않아 tmux·btop 등이 120×32 기본 크기로 그려지던 문제. 접속이 끝나면 지금 창 크기를 다시 보냅니다.

### 세션 유지(tmux) — 이어 쓸 세션 고르기

같은 서버를 분할로 두 번 열면 두 창이 한 tmux 세션에 붙어 똑같은 화면을 보여 주던 문제를 고치면서, 접속할 때 어느 세션에 붙을지 고를 수 있게 했습니다.

- 세션 유지가 켜진 **SSH 서버**에 접속하면 셸을 열기 전에 그 서버의 tmux 세션 목록을 봅니다. 그 서버의 세션은 `bt-<별칭>`과 새로 만든 `bt-<별칭>-2`, `-3` …입니다(tmux 세션 이름을 정했으면 그 이름이 기준).
- 이전 세션이 있으면 **선택 창**이 뜹니다.
  - 세션마다 실행 중인 프로그램, 마지막 활동, 만든 때를 보여 줍니다.
  - 다른 창(이 앱이나 다른 PC)에서 보고 있는 세션은 **다른 창에서 사용 중**으로 표시합니다.
  - 기본 선택은 아무도 보고 있지 않은 최근 세션입니다. 모두 사용 중이면 **새 세션**이 선택됩니다.
  - 🗑 로 세션을 끝낼 수 있습니다(`tmux kill-session`, 확인 후).
  - 취소하면 접속하지 않습니다. Enter 로 다시 시도할 수 있습니다.
- 이전 세션이 없으면 묻지 않고 새로 만듭니다.
- 묻지 않는 경우:

| 상황 | 붙는 세션 |
| --- | --- |
| 연결이 끊겨 자동 재접속 | 그 창이 쓰던 세션 |
| 앱을 다시 켜 탭·분할 복원 | 그 창이 쓰던 세션(세션 이름을 작업 공간에 함께 저장). 이전 버전에서 저장한 배치는 쉬는 세션 |
| 폴더 전체를 그리드로 열기 | 서버마다 아무도 보고 있지 않은 최근 세션, 없으면 새 세션 |

- 창 머리의 **유지** 표시에 세션 번호가 붙습니다(예: `유지 2`). 마우스를 올리면 세션 이름이 보입니다.
- 로컬 터미널(macOS·Linux·WSL)은 예전처럼 세션 하나에 바로 붙습니다.

### 세션 유지 — 서버 확인과 tmux 설치

- 서버 편집의 세션 유지 옆 **서버 확인**: 접속해서 tmux 버전, 배포판, root·sudo 여부, 패키지 관리자를 확인합니다. 저장하기 전 설정으로도 확인할 수 있습니다.
- tmux 가 없으면 배포판에 맞는 설치 명령을 보여 줍니다.

| 패키지 관리자 | 설치 명령 (root 가 아니면 앞에 `sudo`) |
| --- | --- |
| apt | `apt-get update && apt-get install -y tmux` |
| dnf / yum | `dnf install -y tmux` / `yum install -y tmux` |
| zypper | `zypper --non-interactive install tmux` |
| apk | `apk add tmux` |
| pacman | `pacman -S --noconfirm tmux` |
| brew (macOS) | `brew install tmux` |

- **저장하고 터미널에서 설치**: 서버를 저장하고 새 탭에서 접속해 설치 명령을 입력해 줍니다. 이 탭은 세션 유지 없이 열리며, sudo 비밀번호는 터미널에서 직접 입력합니다. 앱이 sudo 비밀번호를 받거나 저장하지 않습니다. **복사** 버튼도 있습니다.
- root 도 아니고 sudo 도 없는 계정이면 서버 관리자에게 설치를 요청하도록 안내합니다.
- 접속했는데 서버에 tmux 가 없으면 터미널에 서버 확인 메뉴를 안내합니다.

### 세션 유지 — 찾기 쉽게

- 세션 유지 스위치를 서버 편집 **고급** 탭에서 **기본** 탭으로 옮겼습니다.
- 사이드바에서 세션 유지가 켜진 서버 이름 옆에 겹친 네모 아이콘을 표시합니다.

### SSH 키 등록

비밀번호로 로그인하는 서버에 이 PC 의 공개키를 등록합니다(`ssh-copy-id` 와 같은 일).

- 대상: 인증 방식이 **비밀번호** 또는 **매번 묻기**인 SSH 서버. 사이드바 항목에 마우스를 올리면 🔑 버튼이, 우클릭 메뉴에 **SSH 키 등록…**이 나옵니다.
- 등록하기 전에 `~/.ssh/*.pub` 목록에서 키를 고릅니다. 파일 이름, 종류, 주석, SHA256 지문과 어느 서버(`user@host`)의 `~/.ssh/authorized_keys` 에 넣을지 보여 줍니다.
  - ed25519 → ecdsa → rsa 순으로 정렬하고 첫 키를 미리 고릅니다.
  - 짝이 되는 개인 키가 없는 `.pub` 은 **개인 키 없음**으로 표시합니다(등록해도 이 PC 에서는 그 키로 로그인할 수 없음).
- 접속은 평소와 같습니다. 저장된 비밀번호를 쓰고, 없으면 묻고, 호스트 키 확인과 점프 호스트도 그대로 거칩니다.
- **이미 등록된 키면 아무것도 바꾸지 않습니다.** 주석이 다르거나 앞에 `from="..."` 같은 옵션이 붙어 있어도 키 본문이 같으면 같은 키로 봅니다.
- 서버에 `~/.ssh` 나 `authorized_keys` 가 없으면 권한 700/600 으로 만들고, 파일 끝에 줄바꿈이 없으면 보충해 마지막 키와 붙지 않게 합니다. SELinux 서버는 `restorecon` 으로 보안 문맥을 맞춥니다.
- 등록한 뒤에도 서버 설정은 비밀번호 로그인 그대로입니다.

### 터미널 링크(OSC 8) 열기

Claude Code 의 `/login` 주소처럼 프로그램이 링크로 출력한 주소(OSC 8 하이퍼링크)를 눌러 확인해도 브라우저가 열리지 않던 문제를 고쳤습니다.

- 그냥 클릭: 앱 확인 창에 **주소 전체**를 보여 주고 **열기**를 누르면 기본 브라우저로 엽니다. 링크로 보이는 글자와 실제 주소가 다를 수 있어서 확인합니다.
- Ctrl+클릭(macOS ⌘+클릭): 묻지 않고 바로 엽니다. 화면의 일반 URL 과 같습니다.
- `http`/`https` 주소만 엽니다.

### Windows 계정 잠금 해제 기본 켜기

- Windows 에서 처음 볼트를 만들 때 **Windows 계정으로 잠금 해제** 체크가 기본으로 켜져 있습니다. 볼트 키를 `safeStorage`(DPAPI)로 암호화해 이 PC 에만 보관하고, 앱을 켜면 자동으로 잠금이 풀립니다. Git 동기화·백업에는 들어가지 않습니다.
- 체크를 풀고 만들 수 있고, 나중에 **설정 → 보안·계정**에서 켜고 끌 수 있습니다.
- 이미 만든 볼트의 설정은 바꾸지 않습니다.

### 서버 쪽 동작 메모 (개발용)

- 서버에서 실행하는 스크립트(키 등록, tmux 목록, 서버 확인)는 `sh -s` 표준입력으로 보냅니다. 로그인 셸이 fish·csh 여도 되지만 `sh` 가 없는 서버(Windows OpenSSH 등)에서는 실패하고 오류를 보여 줍니다.
- 관련 코드: `src/main/persist.ts`(tmux 이름·목록·확인 스크립트), `src/main/transports/ssh.ts`(`execSh`, 세션 고르기), `src/main/sshKeys.ts`(키 목록·등록, 서버 확인), `src/renderer/src/components/UiRequestDialog.tsx`(세션 선택 창), `SshKeyDialog.tsx`, `HostEditor.tsx`.

## 차후 과제

### Windows Hello 로 볼트 잠금 해제 확인

- 현재: Windows 에서 **설정 → 보안·계정 → Windows 계정으로 잠금 해제**를 켜면 볼트 키를 Electron `safeStorage`(DPAPI)로 암호화해 이 PC 에만 보관합니다(Git 동기화·백업에는 들어가지 않음). 같은 Windows 계정으로 로그인해 있으면 **추가 확인 없이** 열립니다.
- 목표: macOS 의 Touch ID 처럼, `safeStorage` 로 볼트 키를 꺼내기 전에 Windows Hello(PIN·지문·얼굴) 확인을 받습니다. 확인을 취소하거나 Hello 를 쓸 수 없으면 마스터 비밀번호로 엽니다.
- 방법 후보: Electron 에 Windows Hello API 가 없으므로 WinRT `Windows.Security.Credentials.UI.UserConsentVerifier`(`CheckAvailabilityAsync`, `RequestVerificationAsync`)를 부릅니다.
  - PowerShell 로 호출: 추가 모듈이 필요 없지만 PowerShell 시작에 1~2초가 걸리고, 확인 창이 앱 창 뒤에 뜨지 않게 처리해야 합니다.
  - 네이티브 모듈: 빠르고 창 연결이 자연스럽지만 빌드·서명 대상이 늘어납니다.
- 관련 코드: `src/main/vault.ts` 의 `tryOsUnlock`(macOS 는 여기서 `promptTouchID`), 설정 문구는 `src/renderer/src/platform.ts` 의 `osUnlockText`.
